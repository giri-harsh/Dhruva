# `reference/golden/` — golden vectors for the reference engine

Fixed (input → exact output) pairs for the implementations in
`reference/anchor_ref/`. Kamal's Kotlin `core/` regression-tests against these
so a port that "compiles" but computes differently is caught (PRD §5.3, §10.5).

| file | reference | generated by | Python test |
|---|---|---|---|
| `strapdown_vectors.json` | B2 strapdown DR | `generate.py` | `ml/tests/test_reference_golden.py` |
| `eskf_vectors.json` | B3 ESKF (Kamal's) | added to `generate.py` once `anchor_ref/eskf.py` lands | — |

**Never hand-edit the JSON.** Change `generate.py` and re-run
`python reference/golden/generate.py`. `ml-ci.yml` runs the reproduce test on
every push; add a stale-artefact `git diff --exit-code` check here the same way
`contracts-ci.yml` does once this is stable.

Vector format:
```json
{ "tolerance_abs": 1e-6, "dt_s": 0.1,
  "vectors": [ { "name": "...",
                 "input":   { "feat_window": [[ax,ay,az,gx,gy,gz], ...], "v0_mps": .., "heading0_rad": .. },
                 "expected": { "east_m": [...T+1...], "north_m": [...], "heading_end_rad": .. } } ] }
```
`feat_window` is the frozen model-contract layout (`contracts/model_io`,
`contracts/frame_convention.md`): aligned vehicle-frame linear accel + gyro.
